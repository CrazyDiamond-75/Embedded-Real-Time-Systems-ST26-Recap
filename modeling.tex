\chapter{Modeling Dynamic Behaviours}
In this chapter we will look at different dynamic mechanisms to mathematically model environment and system using so-called \emph{actor-based} systems.

\section{Continuous Dynamics} \label{sec:1}
Continuous dynamics directly mimic continuous physical processes.
An example where continuous dynamics are used to control an embedded system is a proportional integral differential (PID) controller in a helicopter which is used to cancel out the torque generated by the main rotor using the side rotor.

Generally, the dynamical models in this chapter act on functions between time and some value.

\begin{definition}[General Physical Axioms]
    In the model we define position and angle as functions on time.
    \begin{IEEEeqnarray*}{c}
        x : \R \rightarrow \R^3 \\
        \theta : \R \rightarrow \R^3
    \end{IEEEeqnarray*}
    From this we can obtain the (angular) velocity and acceleration as the respective first and second differential.
    \begin{IEEEeqnarray*}{c}
        \ddot x = \partial \dot x = \partial \partial x
    \end{IEEEeqnarray*}
    If we add a constant mass \(M \in \R\), we can furthermore obtain force by Newton's second law.
    \begin{IEEEeqnarray*}{c}
        F(t) = M \cdot \ddot x(t)
    \end{IEEEeqnarray*}
    If we have a radius \(r \in \R\) and an inertia tensor \(I : \R \rightarrow \R^{3 \times 3}\), torque can be found for a point-mass using either
    \begin{IEEEeqnarray*}{c}
        T(t) = r \cdot F(t)
    \end{IEEEeqnarray*}
    or
    \begin{IEEEeqnarray*}{c}
        T(t) = \partial\left(I(t) \cdot \dot \theta\right).
    \end{IEEEeqnarray*}
    For one dimension and static inertia tensor, this boils down to
    \begin{IEEEeqnarray*}{c}
        T_y(t) = I_{yy} \cdot \ddot \theta_y(t)
    \end{IEEEeqnarray*}
    which can be written in integral form
    \begin{IEEEeqnarray*}{c}
        \dot \theta(t) = \dot \theta(0) + 1/I_{yy} \int_0^t T_y(\tau) \text d\tau.
    \end{IEEEeqnarray*}
\end{definition}

These physical processes are computationally hard to model, as a computer can not possibly predict the future, or solve complex integrals to direct equations.
This is why in the \emph{actor model of systems}, the model calculates general feedback integrals by using approximations.

\begin{definition}[Actor Model of Systems]
    In continuous dynamics, the actor model of systems is defined by using so-called \emph{actors}, which are functions on functions of time, which we call \emph{signals}.
    For example
    \begin{IEEEeqnarray*}{c}
        S : (\R \rightarrow \R) \rightarrow (\R \rightarrow \R)
    \end{IEEEeqnarray*}
    is an actor.

    As already mentioned, a computer can not predict the future, but this model helps by keeping the history in mind.
    The \emph{integrator} actor \(I : (\R \rightarrow \R) \rightarrow (\R \rightarrow \R)\) can be thus defined.
    \begin{IEEEeqnarray*}{c}
        I(x)(t) = x(0) + \int_0^t \dot x(\tau) \text d\tau
    \end{IEEEeqnarray*}
    Here the actor has a parameter \(x(0)\), the initial value, and produces a value function \(x : \R \rightarrow \R\) based on initial value and acceleration \(\dot x\), which is the input of the actor.

    An actor can also have multiple signals as inputs, see \(\oplus : (\R \rightarrow \R)^2 \rightarrow (\R \rightarrow \R)\) with
    \begin{IEEEeqnarray*}{c}
        \oplus(x, y)(t) = x(t) + y(t).
    \end{IEEEeqnarray*}
\end{definition}

\section{Discrete Dynamics} \label{sec:2}
In discrete dynamics we do not look at signals which provide input at every moment, but which are only \emph{present} sometimes.

\newcommand{\prst}{\texttt{present}}
\newcommand{\abst}{\texttt{absent}}

\begin{definition}[Pure and discrete signals]
    A signal is called \emph{pure} if it is of form \(\R \rightarrow \{\abst, \prst\}\) or \(\R \rightarrow \{\abst\} \cup S\) for some set \(S\).
    We define a pure signal \(x\) to be \emph{discrete} iff
    \begin{IEEEeqnarray*}{c}
        \exists f \in \Z^{\{t \in \R \mid x(t) \ne \abst\}}, f \text{ is injective} : \forall t_1, t_2 \in T: t_1 < t_2 \Rightarrow f(t_1) < f(t_2)
    \end{IEEEeqnarray*}
    In other words, a signal \(x\) is discrete iff there exists an one-to-one function on the set of all moments, where \(x\) was not absent to \(\Z\), which is order-preserving.
    All elements of this set have to be ordable on \(\Z\).
    Alternatively, if we assume, that there exists a minimal or first time in which \(x\) was present, the function can also map to \(\N\).
    Note, that countability does not imply discreteness!

    We call an actor on discrete signals discrete, iff the output signal is also discrete.
    Note, that this is not trivial, the composition of two discrete signals does not have to be discrete.

    \emph{Reactions} of a discrete system are triggered by the environment in which the actor operates---it \emph{reacts}.
    In the case that an actor produces an output, which happens on reaction, we call this output \emph{valuation} of \emph{type} \(V\), where \(V\) is the domain of the domain of the actor.
\end{definition}

As mentioned, we consider a discrete actor to react if, but not only if it changes its internal state, this can be done in different ways.
Final state machines (FSM) can be used as a \emph{refinement} of a discrete actor to define its behaviour.

\begin{definition}[Final State Machines]
    FSMs are mathematical constructions consisting of \emph{states}, \emph{transitions}, and an \emph{initial} state.
    A FSM starts in the initial state.
    Transitions are of form \(s, g \rightarrow s', o\), where \(s\) is the state the transition starts in, \(g\) is the \emph{guard} of the transition, \(s'\) is the state the transition ends in, and \(o\) is the (optimal) output valuation the FSM produces, when the transition is taken.

    A FSM which is the refinement of a discrete actor changes its state if a guard of a possible transition is true.
    The actor produces a value, if the transition it takes has an output valuation, else it is absent.

    The guard of a transition can be based on input signals.
    E.g., \(p_1 \wedge \neg p_2 \vee p_3 = 3\) is true, when \(p_1\) is present, and \(p_2\) is absent, or when \(p_3\) is present with value \(3\).

    A transition can be set \emph{default}, which means it is enabled if no non-default transition is enabled.
    This is highlighted by using a dotted line.
    Every FSM defined implicit default self transitions.
    I.e., if no transition is enabled, the FSM neither reacts nor changes its state---any present input is disregarded, but the system is still well defined.

    It is also possible to define non-deterministic transitions, which is indicated through a red line.
    These transitions enable multiple transitions to be taken at the same time.
    If a FSM contains a non-deterministic transition, it is called a non-deterministic FSM.
    In this case, the set of resulting states becomes the permutation set of all possible states.
\end{definition}

We extend the FSM model using the following model.

\begin{definition}[Extended State Machines]
    Extended state machines (ESMs) add more features in comparison to FSMs.
    The extension brings variables \(v \in \mathcal V\) and enables transitions to use \emph{set actions} \(v := \sigma\), where \(\sigma\) is the new value for \(v\).
    \(\sigma\) can be any right-hand side of an output action---it can thus also be based on input signals.
\end{definition}

We also define some basic terms on SMs.

\begin{definition}
    A transition is called \emph{stuttering}, iff it is enabled and produces an absent output.
    A \emph{behaviour} is a sequence of non-stuttering steps.
    A \emph{trace} is the record of inputs, states, and outputs in a behaviour.
    A \emph{computation tree} is a graphical representation of all possible traces.
\end{definition}

SMs provide a way to mathematically represent the environment of the system and the system itself.
They can be used for designing requirements and analysing the safety of the system.

Currently we do not have defined, \emph{when} a reaction occurs, i.e., when to read the next input values for the signals.
This is vitally important, as we can define ESMs with a default self transition, which increases the value of a variable---the value becomes dependent on the \emph{rate} of reactions, which is currently undefined.
We will go over this notion of time in \cref{sec:6}.

\section{Hybrid Automata}
In \cref{sec:1,sec:2} we defined continuous and discrete automata, in this section we will define \emph{hybrid automata}, which combine both approaches by refining individual states with continuous actors.

In hybrid automata, signals do not have to be discrete---they are allowed to be continuous-time signals.
This again begs the question \emph{when} a reaction happens.
In this model, we define the actor to react \emph{asap}---which depends on the simulation speed, when evaluating the model.

For example, we can define a continuous actor using a hybrid model which contains one state \(s\) with variable \(v = 0\) and default transition \(s, \true \rightarrow s, v, \dot v := 1\).
This hybrid automata defines a continuous actor with no input signal, which outputs the linear function.

\begin{definition}[Hybrid Automata]
    We formally define hybrid automata to be ESMs with continuous input and output signals.
    Moreover, it is allowed to depend the value of a variable in \emph{continuous time}, by setting derivatives of variables in a set action.
    Reactions occur as soon as possible.

    Hybrid automata also define refinements to states which are themselves continuous actors.
\end{definition}

\section{State Machine Compositions}
It is possible to combine different SM-refined (discrete) actors together on a top level.
There are four different compositions with different semantics.
\begin{description}
    \item[Synchronous side-by-side composition] Multiple SMs in parallel with reaction only possible when all SMs react.

    \item[Asynchronous side-by-side composition] Multiple SMs in parallel with non-deterministic reaction when any SM can react.

    \item[Cascade composition] Multiple SMs chained together with output signals as input signals for another SM.

    \item[Feedback composition] Recursive connection of a SM which sets input signals to own output signals.
\end{description}

For the following definitions, we will look at compositions between two SM actors \(A\) and \(B\) with states \(S_A, S_B\), input valuations (or guards) \(i_A, i_B\), output signals \(o_A, o_B\), initial states \(I_A, I_B\), and update function \(u_A : S_A \times i_A \rightarrow S_A \times o_A\), for \(B\) analogous, to represent the transitions.

\begin{definition}[Synchronous Side-by-side Composition]
    In synchronous side-by-side compositions for SMs \(A\) and \(B\), we define the set of states as \(S := S_A \times S_B\), the inputs \(i := i_A \times i_B\), outputs \(o := o_A \times o_B\), initial state \(I := (I_A, I_B)\), and update function \(u : S \times i \rightarrow S \times o,\)
    \begin{IEEEeqnarray*}{c}
        u((s_A, s_B), (v_A, v_B)) = ((s_A', s_B'), (v_A', v_B')),
    \end{IEEEeqnarray*}
    with \((s_A', v_A') = u_A(s_A, v_A)\) and \((s_B', v_B') = u_B(s_B, v_B)\).

    In other words, we just concatenate all input, states, outputs, and derive next output/state by calculating the next state and output for both SMs, and combining them.

    This means that, even though \(A\) and \(B\) may have one input pair, for which \(A\) reacts and \(B\) produces an absent value, the combined SM reacts.
    This is because \(B\) reacts without producing a value---the reactions are triggered by the environment.
\end{definition}

\begin{definition}[Asynchronous Side-by-side Composition]
    In the asynchronous side-by-side composition, the environment chooses if either \(A\) or \(B\) react\footnote{It is also possible, that both actors react. These semantics are not discussed in this model.}.
    This is called \emph{interleaving semantics}.
    Thus we have the same definition as in the synchronous version, but with the rule that the update function \(u : S \times i \rightarrow S \times o\) is defined as
    \begin{IEEEeqnarray*}{c}
        u((s_A, s_B), (v_A, v_B)) =
        \begin{cases}
            ((s_A', s_B), (v_A', \abst)) & \text{when \(A\) reacts,} \\
            ((s_A, s_B'), (\abst, v_B')) & \text{when \(B\) reacts.}
        \end{cases}
    \end{IEEEeqnarray*}

    This is realized using non-deterministic compositions when calculating the composite actor.
\end{definition}

\begin{definition}[Cascade Composition]
    The cascade composition of \(A\) and \(B\) is considered to be the simultaneous and instantaneous reaction of both actors, where the output signal of \(A\) is the input signal of \(B\).
    This is of course only possible if the expression \emph{type checks}, i.e., when \(o_A \subseteq i_B\).

    To construct the composition machine, first form the state space as the cross product of the state spaces of \(A\) and \(B\), and then determine which transitions are taken under what conditions.
    It is important to remember that the transitions are simultaneous, even when one logically causes the other.
\end{definition}

The last possible composition between two actors is the feedback composition.
To define the semantics of such a composition, the question again begs which actor should react \emph{first}.
Tackling this requires defining another model of computation, the \emph{synchronous-reactive} model of computation.

The semantics of a feedback composition should be similar to the cascade composition in the way, that they are simultaneous and instantaneous.
The difference being, that the composed actor does not oscillate in propagating data from one end to the other, but computes a solution instantaneous, where output matches input.
Thus, in a feedback composition of two actors, they react at the same time.

By reorganizing any composition of actors, it can be shown that there is an equal simple feedback composition.

\begin{definition}[Feedback Composition]
    Realizing a feedback composition between \(A\) and \(B\) needs \(o_A \subseteq i_B \wedge o_B \subseteq i_A\).
    As mentioned, any composition can also be rewritten as a feedback composition using one actor, thus we only need to consider \(o_C \subseteq i_C\) if \(C\) is the refined feedback composition of \(A\) and \(B\), which is equivalent to the statement prior\footnote{It has to be noted, that for this case, there are two different versions of \(C\), when composing it, such that there is a connection between \(A\) and \(B\) inside the composed actor. The inner signal can also be mapped externally and vice versa. For this example we consider a version where \(A\) and \(B\) are not connected in the body of \(C\) but using a signal which is the two signals concatenated.}.

    The goal is finding the \emph{fixed point} signal \(s : \N \rightarrow o_C \cup \{\abst\}\) which flows from the output of \(C\) to its input.
    \(s\) must hold \cref{eq:1} to be a fixed point, where \(\textsf C : (\N \rightarrow i_C \cup \{\abst\}) \rightarrow (\N \rightarrow o_C \cup \{\abst\})\) is the actor function of \(C\).

    \begin{IEEEeqnarray}{c} \label{eq:1}
        \textsf C(s) = s
    \end{IEEEeqnarray}

    To find \(s\), we consider the \emph{firing function} \(f_C : \N \rightarrow (i_C \cup \{\abst\} \rightarrow o_C \cup \{\abst\})\) of \(C\) which is a recomposed version of the actor function to determine the signal at reaction \(n \in \N\).
    This transforms \cref{eq:1} into \cref{eq:2}, which is also called a fixed point.

    \begin{IEEEeqnarray}{c} \label{eq:2}
        \forall n \in \N : s(n) = (f_C(n))(s(n))
    \end{IEEEeqnarray}
\end{definition}

To find fixed points in arbitrary feedback compositions, we can deduce the simple feedback composition, as mentioned.
Many simplified feedback compositions can shown to be \emph{well-formed} which implies the existence of an unique fixed-point.
In this case, we can construct a resulting actor based on the fixed point \(s\).

\begin{definition}[Well-formedness]
    When finding a fixed point with \cref{eq:2}, there may be two problems.
    The fixed point may not exist, or it is not unique.
    In either case, the system is called \emph{ill-formed}---the feedback composition is unstable.
    If this is not the case, the system is called \emph{well-formed}.
\end{definition}

As well-formedness is not equivalent to the existence of a fixed point, there are ill-formed compositions.
This is the case when the system has multiple fixed points.
Nevertheless, it is possible to find unique fixed points for many actors using an algorithm to test for \emph{constructiveness}.

\begin{algorithm}[Determining Constructiveness] \label{alg:1} \hfill
    \begin{enumerate}
        \item Start with \(s(n)\) unknown.
        \item Determine \((f_C(n))(s(n))\) by looking at transitions, starting from the initial state and looking if there exists a value which is output by all transitions.
            This is needed, as the input at time \(n\) is unknown.
        \item Repeat 2. until all values in \(s(n)\) become known or no more progress can be made.
        \item If unknown values remain, the model is not constructiveness, else it is.
    \end{enumerate}
\end{algorithm}

It is vitally important to remember \textbf{not} to search for a fixed point by matching all inputs and outputs for all transitions, as while this is a correct approach, for arbitrary state machine actors with big \(o_C\) this can take too much time, as this is an exhaustive search---which may be impossible if \(o_C\) has infinite types.
To demonstrate this, look at Figure 6.6 in LeeShia\footnote{\url{https://ptolemy.berkeley.edu/books/leeseshia/releases/LeeSeshia_DigitalV2_3.pdf\#figure.6.6}}.
When applying \cref{alg:1} to this example, it does not find a fixed point in state \textsf{s1}, as \(1 \ne \abst\).
There is the fixed point \(\abst\) though, which is derived from the transition from \textsf{s1} to \textsf{s2}, which can not be found using the algorithm---this model is well-formed but not constructive!

\section{Dataflow Models}
As opposed to previous semantics, in \emph{dataflow models} a reaction is not simultaneous---if data flows from an actor \(A\) to an actor \(B\), it is put into a FIFO buffer in between while \(A\) produces, and \(B\) consumes.
There are different dataflow semantics, in this lecture we will mainly look at \emph{synchronous dataflow} (SD).

\subsection{Synchronous Dataflow}
The goal in SD is finding schedules for firing actors, such that all token productions and consumptions are balanced, else the consumption buffer may overflow, or run out of tokens.
To help with this task, we can define \emph{balance equations} between connected actors.

\begin{definition}[Balance Equations]
    Suppose we have \(n \in \N\) actors \([n]\) with \(m \in \N\) connectors.
    Define the connection matrix \(\Gamma \in \N^{m \times n}\) where \(\Gamma_{i*}\) is the vector which defines connector \(i\).
    The value \(\Gamma_{ij}\) is positive if connector \(i\) is connected with \(j\) and \(j\) produces tokens;
    it is negative if \(j\) consumes tokens;
    it is zero, if \(j\) is not connected through connector \(i\).

    The \emph{balance equation} of the SD system is finding \(q \in \N^n\), such that \(\Gamma \times q = \vec 0\).
    A non-zero solution for this equation tells how often in relation each actor must fire.

    If the rank of \(\Gamma\) is \(n-1\), there exists a non-trivial solution for the balance equation.
    If it is \(n\), which is the only other possibility, there does not exist a non-trivial solution.

    As a reminder, the rank of \(\Gamma\) can be determined, by applying Gaussian elimination and reducing as many rows as possible.
    The count of non-zero values in the diagonal of the resulting matrix is the rank of \(\Gamma\).
\end{definition}

If a solution is found for a balance equation, there exists a schedule for the system by decomposing the vector into a sum of unity vectors.
E.g., solution \((1,2,1)^T\) is decomposed as \((1,0,0)^T + (0,1,0)^T + (0,1,0)^T + (0,0,1)^T\), which becomes the schedule \((1;2;2;3)\).
For this it is advised to reduce to the minimal solution by scaling it to minimal length with integer values.

\subsection{Other Variants}
In \emph{dynamic dataflow} production/consumption rate depend on data, which makes the problem undecidable in means of finding a schedule or proving that a schedule runs with bounded memory.

There also exists \emph{structured dataflow} or \emph{homogeneous} SDF, which is a restriction of dynamic dataflow to make scheduling decidable.

Another variant are \emph{Petri nets} which use \emph{places} to store tokens one-by-one which move using transitions to other places.
Each place can only store one token, which can be used to model different programs.
Petri nets with finite possible states are equivalent to finite SMs.

\section{Timed Models of Computation} \label{sec:6}
In this section we will go over different mechanisms on when to trigger reactions/computations in discrete dynamics, synchronous reactive, or hybrid models.
To simplify for now, we will assume discrete time, which postulates that outputs are computed instantaneous when its inputs are ready---there is no computation time, or it is negligible.

The goal of this section is to define behaviour and implementation of a \emph{tick function}, which determines, when the model should react.

\subsection{Event-Triggered Models}
In event-triggered models, reactions only happen on outside events, e.g., a sensor-read button press.
In our model this would be an input signal which is present.
The tick function is defined as an event trigger, which sends a tick, exactly when any signal becomes present.

The problem with this mechanism is, that reactions suddenly can not be triggered by internal events.
As an example, consider an ESM with initial state \textsf{s}.
This state also has a refinement based on variable \(x := 0\) and \(\dot x := 1\).
Now we define a transition to state \textsf{s} with guard \(x = 1\), output \(x\), and set action \(x = 0\).
If there is no input signal, or the input signal is not present directly after \(t=1\), the ESM will not output \(x\).
Even worse, if the ESM reacts at \(t=2\), it will output \(2\), as the value as progressed further, than it should have, as the ESM can not react by itself.

\subsection{Time-Triggered Models}
In time-triggered architectures, actors react according to a distributed clock.
This means, whenever the clock ticks, buffered inputs, if any, are distributed to the actor and it reacts.
The tick function can be implemented using specific hardware for clocks, e.g., piezo-electric quartz crystals.

With this notion, there still come up problems, as event-driven reactions are delayed to the next tick.

\subsection{Multiform Notion of Time}
In multiform time, both events and a clock trigger reactions.
It is implemented by combining the two approaches together.

There still remains the problem, that if the clock produces not enough ticks, internal reactions are delayed too much, which can be dangerous in the real-time systems context.

\subsection{Eager Semantics}
The best model should trigger reactions as soon as possible, in the timing relevant point in time, as defined in synchronous reactive semantics.
This ideal is also called \emph{eager semantics}.

Implementing eager semantics has a lot of requirements to make them realistically feasible for real-time systems.
The main step in doing this implementation is using \emph{dynamic ticks}.

Dynamic ticks are an extension of multiform time, where the clock additionally stores two values, \textsf{deltaT} the time since last tick and \textsf{sleepT} requested delay until next tick.
The first is calculated on each tick, when reacting due to an event.
The latter is set on each reaction based on information about the automata in its current state.
If, while waiting, an event happens, and the sleep is interrupted, \textsf{sleepT} is changed based on \textsf{deltaT}.
